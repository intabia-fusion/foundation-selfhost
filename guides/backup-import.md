# Backup Import & Restore Guide / Импорт и восстановление бэкапа

Download a workspace backup from a Huly cloud instance and restore it into your
self-hosted Platform.

Скачайте бэкап рабочего пространства из облачного Huly и разверните его в вашей
self-hosted Платформе.

---

## English

### Overview

The easiest path is the interactive wizard `import-from-huly.sh`, which walks you
through every step. Under the hood it uses:

- `import-backup.mjs` - downloads all backup files **and large blobs** of a
  workspace (with retry, resume, and a live progress bar).
- `create-workspace.sh` - creates a local workspace and assigns it to an
  existing local user.
- `backup-restore.sh` - restores the data and uploads the blobs into the local
  datalake.

All connection parameters are read from `config/platform.conf` (generated by
`setup.sh`).

### Step 0. Prerequisites - create the local user first

The restored workspace needs an **owner**, and that owner must be an existing
local user. Create it before running the import:

1. Make sure the platform is running (`./up.sh`).
2. Open the platform in your browser: `http://<host>` (the address you set in
   `setup.sh`, e.g. `http://localhost:8080`).
3. Sign up with an email and the requested name.

> [!IMPORTANT]
> **Emails (OTP / confirmation codes) are NOT sent to the real internet.**
> The self-hosted platform delivers all mail to a local **Mailpit** inbox.
> Open it to read the confirmation code:
>
> ```
> http://<host>:8025
> ```
>
> (Port is `MAILPIT_HTTP_PORT` in `config/platform.conf`, default `8025`.)
> Find the latest message, copy the OTP / link, and finish the sign-up.

Remember the email you used - the wizard asks for it as the workspace owner.

### Step 1. Get the backup URL and token

Open your workspace in the Huly web app and go to the backup settings:

```
https://huly.app/workbench/<workspace>/setting/setting/backup
```

On this page (**Settings -> Backup -> Backup Files**):

1. Under **The URL of a backup directory...**, click **Copy to clipboard** to
   get the backup URL, e.g.
   `https://backup.huly.app/api/backup/<workspace-id>/index.html`.
2. Next to **A bearer token is required to access the backup**, click
   **Copy to clipboard** to get the token.

> [!TIP]
> The same page shows backup stats (snapshots, file count, size) and lets you
> download `index.json` / `index.html` directly to verify access first.

### Step 2. Run the wizard

```bash
./import-from-huly.sh
```

The wizard asks, in order:

1. **Backup URL** (paste from Step 1).
2. **Bearer token** (paste from Step 1, input hidden).
3. **Workspace name** - any readable name you like (not a UUID), e.g. `my-team`.
4. **Owner email** - the existing local user from Step 0.

It then downloads the backup + blobs, creates the workspace, restores the data,
and uploads the blobs. When it finishes, log in as the owner to see the
restored workspace.

### Manual steps (advanced)

If you prefer to run the stages yourself:

```bash
# 1. Download into a UUID-keyed folder (backups/<huly-ws-uuid>).
#    Re-running reuses already-downloaded files - nothing is deleted.
node import-backup.mjs --url https://backup.huly.app/api/backup/<ws-uuid>/index.html \
  --token-file ./token.txt        # default --out is ./backups/<ws-uuid>

# 2. Create the local workspace for an existing user
./create-workspace.sh my-team --owner-email user@example.com
#    (add --create-owner --owner-pass <pass> to also create the account)

# 3. Restore data + upload blobs
./backup-restore.sh ./backups/<ws-uuid> my-team
```

> [!NOTE]
> Downloads are stored under `backups/<huly-workspace-uuid>/`, not under the
> local name you pick. Choosing a different local name on a re-run reuses the
> same download. Downloaded files are never deleted.

### Troubleshooting

- **401 Unauthorized when downloading** - token expired or not an owner/admin.
  Get a fresh token (Step 1).
- **No confirmation email** - check Mailpit (`http://<host>:8025`), not your real
  mailbox.
- **Workspace creation fails** - the owner user does not exist yet. Sign up
  first (Step 0).
- **Network `<name>_platform_net` not found** - the platform is not running
  (`./up.sh`).
- **Blob upload FAIL** - datalake must be reachable on `localhost:4031`; ensure
  `datalake` and `minio` are healthy.

## По-русски

### Обзор

Самый простой путь - интерактивный мастер `import-from-huly.sh`, проводящий
через все шаги. Внутри использует:

- `import-backup.mjs` - скачивает все файлы бэкапа **и большие блобы** рабочего
  пространства (с повторами, докачкой и прогресс-баром).
- `create-workspace.sh` - создаёт локальное рабочее пространство и привязывает к
  существующему локальному пользователю.
- `backup-restore.sh` - восстанавливает данные и заливает блобы в локальный
  datalake.

Все параметры подключения берутся из `config/platform.conf` (создаётся `setup.sh`).

### Шаг 0. Подготовка - сначала создать локального пользователя

Восстановленному пространству нужен **владелец** - существующий локальный
пользователь. Создайте его до импорта:

1. Платформа должна быть запущена (`./up.sh`).
2. Откройте платформу в браузере: `http://<хост>` (адрес из `setup.sh`,
   например `http://localhost:8080`).
3. Зарегистрируйтесь с email и именем.

> [!IMPORTANT]
> **Письма (OTP / коды подтверждения) НЕ уходят в реальный интернет.**
> Self-hosted платформа доставляет всю почту в локальный ящик **Mailpit**.
> Откройте его, чтобы прочитать код подтверждения:
>
> ```
> http://<хост>:8025
> ```
>
> (Порт - `MAILPIT_HTTP_PORT` в `config/platform.conf`, по умолчанию `8025`.)
> Найдите последнее письмо, скопируйте OTP / ссылку, завершите регистрацию.

Запомните использованный email - мастер спросит его как владельца пространства.

### Шаг 1. Получить URL бэкапа и токен

Откройте рабочее пространство в web-приложении Huly и перейдите в настройки
бэкапа:

```
https://huly.app/workbench/<workspace>/setting/setting/backup
```

На странице (**Settings -> Backup -> Backup Files**):

1. В блоке **The URL of a backup directory...** нажмите **Copy to clipboard** -
   получите URL, например
   `https://backup.huly.app/api/backup/<id-пространства>/index.html`.
2. Рядом с **A bearer token is required to access the backup** нажмите
   **Copy to clipboard** - получите токен.

> [!TIP]
> На этой же странице видна статистика бэкапа (снапшоты, число файлов, размер) и
> прямое скачивание `index.json` / `index.html` для проверки доступа.

### Шаг 2. Запустить мастер

```bash
./import-from-huly.sh
```

Мастер спросит по порядку:

1. **URL бэкапа** (вставьте из Шага 1).
2. **Bearer токен** (вставьте из Шага 1, ввод скрыт).
3. **Имя пространства** - любое понятное имя (не UUID), например `my-team`.
4. **Email владельца** - существующий локальный пользователь из Шага 0.

Далее мастер скачает бэкап + блобы, создаст пространство, восстановит данные и
зальёт блобы. По завершении войдите под владельцем - увидите восстановленное
пространство.

### Ручные шаги (для продвинутых)

```bash
# 1. Скачать в папку по UUID (backups/<huly-ws-uuid>).
#    Повторный запуск переиспользует уже скачанное - ничего не удаляется.
node import-backup.mjs --url https://backup.huly.app/api/backup/<ws-uuid>/index.html \
  --token-file ./token.txt        # по умолчанию --out = ./backups/<ws-uuid>

# 2. Создать локальное пространство для существующего пользователя
./create-workspace.sh my-team --owner-email user@example.com
#    (добавьте --create-owner --owner-pass <pass> чтобы создать и аккаунт)

# 3. Восстановить данные + залить блобы
./backup-restore.sh ./backups/<ws-uuid> my-team
```

> [!NOTE]
> Скачанное хранится в `backups/<huly-workspace-uuid>/`, а не под выбранным
> локальным именем. Другое имя при повторном запуске переиспользует ту же
> загрузку. Скачанные файлы никогда не удаляются.

### Решение проблем

- **401 Unauthorized при скачивании** - токен истёк или вы не владелец/админ.
  Получите свежий токен (Шаг 1).
- **Не приходит письмо** - смотрите Mailpit (`http://<хост>:8025`), не реальный
  почтовый ящик.
- **Ошибка создания пространства** - пользователь-владелец ещё не создан.
  Сначала зарегистрируйтесь (Шаг 0).
- **Network `<name>_platform_net` not found** - платформа не запущена
  (`./up.sh`).
- **Blob upload FAIL** - datalake должен быть доступен на `localhost:4031`;
  проверьте `datalake` и `minio`.
